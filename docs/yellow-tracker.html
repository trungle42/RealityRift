Colour Tracker: user guide

Hold a yellow, a blue and a red object up to your webcam and watch each one leave a trail in its own colour. Detection pauses and resumes every 5 seconds, and every pause wipes all the trails, so each round starts on a clean screen.

  • Python 3.12
  • Yellow · blue · red
  • OpenCV colour detection (no ML model)
  • ~27 fps on a laptop webcam
  • 55 tests, no camera needed

What it does

The program watches your webcam and looks for three things at once: the largest yellow blob, the largest blue blob and the largest red blob in view (the ball, foam head or tape on a stick). For each colour it draws a line, in that colour, through every place the blob has been. Move a stick around and its line follows it. The colours are tracked independently, so you can use one, two or all three at the same time.

Every 5 seconds detection switches state, for all colours together. While it is ON the paths grow. When it switches OFF every path is erased and nothing is tracked until it switches back on, when new paths begin.

Use sticks that are not yellow, blue or red. The tracker follows any blob of those colours it sees, so a coloured stick would drag the tracked point away from the ball. Keep other things of those colours (clothes, posters) out of the shot, and note that red is the easiest to confuse with skin; see Troubleshooting.

Quick start

Everything below runs from the cv_2/ folder.

  1. Create the environment once. On Windows on ARM64 (Snapdragon) it must use the x86_64 Python 3.12, because OpenCV has no ARM64 Windows build. On a Mac or x64 PC use uv venv --python 3.12 .venv. 
    uv venv --python cpython-3.12-windows-x86_64-none .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
  2. Run the demo. 
    .venv\Scripts\python.exe -m tools.demo
  3. Hold your yellow, blue and/or red object in front of the camera and move it. Press m to see what the program counts as each colour, q to quit.

The screen

The view is mirrored like a selfie camera: move the stick to your right and the trail moves right on screen.

When the state is OFF the status banner turns red, a red border appears around the picture, the bottom says paused - traces erased, and no trail or marker is drawn.

The on/off cycle

The clock starts when the program starts, with detection ON. It then alternates every period seconds (5 by default). The moment it goes OFF every colour's path is erased; the OFF phase just waits. When it goes ON again brand new paths start from wherever the objects are. All colours switch together.

Change the length with --period or YT_PERIOD. If the object disappears for more than a quarter of a second while ON, the line is broken rather than joined across the gap, so you never get a long straight stroke to where it reappeared.

How it works

There is no trained model. Each frame goes through a short pipeline of ordinary image processing, all in tracker/.

1. Colour mask

detector.py

The frame is blurred and converted to HSV (hue / saturation / value) once. For each colour, every pixel whose hue is in that colour's band, and that is vivid and bright enough, is marked. Red's hue wraps around the ends of the scale, so it uses two bands. Small speckles are removed and small holes (shiny highlights) are filled.

2. Biggest blob

detector.py

For each colour, the outline with the largest area wins. If it is smaller than YT_MIN_AREA of the frame it is treated as noise and that colour is not detected. Its centre of mass is the tracked point.

3. Smoothing

pipeline.py

The point is blended with the previous one (weight 0.6 on the new position), which hides pixel-level jitter without making the trail lag noticeably.

Finding vs following

detector.py

A new object needs the strict thresholds. Once found, it is followed with relaxed ones near its last position and kept for 0.5 s after a dropout, so uneven lighting does not make it flicker. See Tuning.

4. Trace

trace.py

Each colour has its own trace. Points are appended to the current line segment. A gap of more than 0.25 s ends the segment. At most 2000 points are kept per colour. The gate clears all traces when ON turns to OFF.

Tuning

Measure your objects (recommended)

Webcam lighting is rarely even. On the development laptop the average brightness differed by more than 2× between one side of the picture and the other. A ball then looks washed out or dim toward one edge, and a fixed colour threshold makes it flicker or vanish there. Instead of guessing numbers, let the tool measure your real objects:

  1. Run python -m tools.tune.
  2. Press 1, 2 or 3 to choose yellow, blue or red.
  3. Click your object in several places: the edge where it disappears, the opposite edge, and the middle (move it between clicks). Each click samples a small patch.
  4. Press p. It prints PowerShell lines such as $env:YT_BLUE_HUE="108-119" that cover every spot you clicked, with a little slack. Paste them into your terminal and start the demo.

c forgets the chosen colour's samples, m toggles the panel showing what the strict detector counts as that colour.

Stays on once found

Detection is forgiving once it has locked on. An object is found with the strict thresholds below, then followed with relaxed ones (slightly wider hue, half the saturation and brightness floors) but only around where it was a moment ago, and it is searched for there for half a second if it drops out. A brand-new object must also be seen in three frames in a row (about a tenth of a second) before it counts, so a single-frame flash of skin or clothing never starts a trace. A followed blob must also be between about a third and twice the size of the last detection, so a lock cannot spread from a small red patch (lips) across the whole face, and a small patch next to the ball (lips) cannot steal it. So a ball that fades toward the bright or dark side keeps its trail instead of flickering, while skin or a wall elsewhere is still ignored because relaxed thresholds are never used to find a new object. Even lighting still helps most: light your face and the scene from the front rather than from one side, use a matte ball (shiny ones wash out), and switch off auto exposure and white balance in your camera app if it has them.

Manual settings

Webcams differ in white balance, so the exact yellow, blue and red differ too. If the tracker misses an object or latches onto something else, press m in the demo: the right-hand pane paints what each detector counts as its colour (yellow, blue or red) on black. Each object should be a solid blob of its own colour and nearly everything else black.

Change settings with environment variables before starting the demo, for example in PowerShell: $env:YT_YELLOW_HUE="18-35"; $env:YT_RED_S_MIN="150"; .venv\Scripts\python.exe -m tools.demo.

Troubleshooting

SymptomLikely cause and fix
One colour is never tracked, its marker never appearsThe object is outside that colour's hue band or too small. Press m; if it is black in the mask, widen that colour's YT_*_HUE or lower its YT_*_S_MIN. Dim or tinted lighting shifts colours, for example yellow towards orange or green.
A colour flickers, or disappears toward one side of the pictureUneven lighting: the object is brighter, dimmer or more washed out there than where the thresholds were set. Run python -m tools.tune and click the object on that side and in the middle, then press p and use the printed lines. Also move or add a light so the scene is lit evenly, and prefer a matte ball. If it only fails when the object is very close to the edge of the picture, the saturation floor (YT_*_S_MIN) is usually the culprit.
A marker jumps to something elseAnother thing of the same colour is bigger than your object (clothes, wall). Remove it from view, or raise that colour's YT_*_S_MIN / narrow its hue band. For each colour the largest blob always wins.
The red marker appears on your lips, face or hand with no red objectWhen first finding an object red only counts round blobs, which rules out lips (a strip). If it still happens, raise YT_RED_MIN_CIRC (try 0.7). If your red object is not round and is never found, lower it instead. Run python -m tools.tune and sample your red object: the printed saturation floor shows how far you can safely raise YT_RED_S_MIN without losing it (lips measured about 125 against a ball of 132 and above, so colour alone separates them poorly). Press m to see which pixels count as red, or leave red out with YT_COLORS=yellow,blue.
The marker sits on the stick, not the ballThe stick is yellow, blue, red or a reddish wood brown. Use a grey, black or white stick, or wrap it in tape.
The line breaks into piecesThe object keeps dropping out of the mask (glare on a shiny surface, motion blur). Lower that colour's YT_*_V_MIN or widen its hue band; brighter, even light helps most.
"Could not open camera 0"Another program (or a demo that did not exit) is holding the webcam. Close it, or pick another camera with --camera 1. On macOS allow camera access for your terminal.
uv pip install fails with "Unknown compiler(s)"You created the venv with the native ARM64 Python. Recreate it with the x86_64 Python as shown in Quick start.
The picture looks flippedThat is the default selfie view. Set YT_MIRROR=0 for the raw orientation.

Output data

Each frame produces a plain dictionary (Pipeline.process(frame)). It is JSON-safe and uses 0-1 coordinates, so it can be sent to a web frontend unchanged. Nothing serves it over the network yet.

{
  "active": true,             // false during the OFF phase
  "secondsLeft": 3.2,         // until the next switch
  "mirrored": true,           // x already flipped to match a selfie view
  "objects": {                // one entry per tracked colour
    "yellow": {               // null when that colour is not detected (all null while OFF)
      "x": 0.71, "y": 0.43,   // centre, 0-1 from the top-left of the (mirrored) view
      "radius": 0.06          // fraction of frame width
    },
    "blue": null,
    "red": { "x": 0.30, "y": 0.72, "radius": 0.04 }
  },
  "traces": {                 // per colour: a list of line segments; empty right after an OFF switch
    "yellow": [
      [[0.20, 0.61], [0.23, 0.58], ...],
      [[0.71, 0.43]]
    ],
    "blue": [],
    "red": [[[0.31, 0.70], [0.30, 0.72]]]
  }
}

tests/test_tracker.py55 tests on synthetic frames with a fake clock.

The tests draw yellow, blue and red balls on sticks (plus skin-, green-, cyan- and magenta-coloured decoys) and drive the clock by hand. They check, among other things, that each colour's path follows its own object without picking up the others, that every path is erased on every OFF switch over several cycles, that no detector runs while OFF, that red is found in both of its hue ranges, that a ball fading toward one side is still followed but not found from scratch, and that a lost object breaks the line. The tests use synthetic images, so they say nothing about your lighting. The default colour bands were hand-tuned on one laptop camera; run python -m tools.tune to fit them to yours.
