Yellow Tracker: user guide

Hold a yellow object up to your webcam and watch it leave a trail. Detection pauses and resumes every 5 seconds, and every pause wipes the trail, so each round starts on a clean screen.

  • Python 3.12
  • OpenCV colour detection (no ML model)
  • ~27 fps on a laptop webcam
  • 17 tests, no camera needed

What it does

The program watches your webcam, finds the largest yellow blob in view (the ball, foam head or tape on your stick), and draws a line through every place that blob has been. Move the stick around and the line follows it.

Every 5 seconds detection switches state. While it is ON the path grows. When it switches OFF the path is erased and nothing is tracked until it switches back on, when a new path begins.

Use a yellow object on a stick that is not itself yellow. The tracker follows any yellow it sees, so a yellow stick would drag the tracked point away from the ball. Keep other yellow things (clothes, posters) out of the shot.

Quick start

Everything below runs from the cv_2/ folder.

  1. Create the environment once. On Windows on ARM64 (Snapdragon) it must use the x86_64 Python 3.12, because OpenCV has no ARM64 Windows build. On a Mac or x64 PC use uv venv --python 3.12 .venv. 
    uv venv --python cpython-3.12-windows-x86_64-none .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
  2. Run the demo. 
    .venv\Scripts\python.exe -m tools.demo
  3. Hold the yellow object in front of the camera and move it. Press m to see what the program considers yellow, q to quit.
CommandWhat it does
python -m tools.demoLive window with the trail and the ON/OFF banner.
python -m tools.demo --period 3Switch every 3 s instead of 5.

The screen

The view is mirrored like a selfie camera: move the stick to your right and the trail moves right on screen.

When the state is OFF the banner turns red, a red border appears around the picture, the bottom says paused - trace erased, and no trail or marker is drawn.

The on/off cycle

The clock starts when the program starts, with detection ON. It then alternates every period seconds (5 by default). The moment it goes OFF the path is erased; the OFF phase just waits. When it goes ON again a brand new path starts from wherever the object is.

Change the length with --period or YT_PERIOD. If the object disappears for more than a quarter of a second while ON, the line is broken rather than joined across the gap, so you never get a long straight stroke to where it reappeared.

How it works

There is no trained model. Each frame goes through a short pipeline of ordinary image processing, all in yellow_tracker/.

1. Colour mask

detector.py

The frame is blurred, converted to HSV (hue / saturation / value) and every pixel whose hue is in the yellow band, and that is vivid and bright enough, is marked. Small speckles are removed and small holes (shiny highlights) are filled.

2. Biggest blob

detector.py

The outline with the largest area wins. If it is smaller than YT_MIN_AREA of the frame it is treated as noise and nothing is detected. Its centre of mass is the tracked point.

3. Smoothing

pipeline.py

The point is blended with the previous one (weight 0.6 on the new position), which hides pixel-level jitter without making the trail lag noticeably.

4. Trace

trace.py

Points are appended to the current line segment. A gap of more than 0.25 s ends the segment. At most 2000 points are kept. The gate clears everything when ON turns to OFF.

Tuning

Webcams differ in white balance, so the exact "yellow" differs too. If the tracker misses your object or latches onto something else, press m in the demo: the right-hand pane is the mask, and white means "counts as yellow". Your object should be a solid white blob and nearly everything else black.

Change settings with environment variables before starting the demo, for example in PowerShell: $env:YT_H_MIN=18; $env:YT_H_MAX=35; .venv\Scripts\python.exe -m tools.demo.

VariableDefaultEffect
YT_H_MIN / YT_H_MAX20 / 25Hue band (OpenCV hue runs 0-179; pure yellow is 30). Widen it if your object is only partly white in the mask; narrow it if neighbouring colours leak in.
YT_S_MIN90Minimum saturation (0-255). Raise it to reject pale, washed-out things such as skin and walls.
YT_V_MIN90Minimum brightness (0-255). Raise it to ignore dark, muddy yellows and shadows.
YT_MIN_AREA0.0006Smallest blob that counts, as a fraction of the frame (about 185 px at 640×480).
YT_PERIOD5Seconds in each ON and each OFF phase.
YT_MIRROR1Selfie-style view. 0 shows the raw camera orientation.
YT_CAMERA0Camera index.
YT_WIDTH / YT_HEIGHT640 / 480Capture size.

Other values (smoothing weight, gap length, point limit) are fields of the Config dataclass in yellow_tracker/config.py.

Troubleshooting

SymptomLikely cause and fix
Nothing is tracked, the marker never appearsThe object is outside the hue band or too small. Press m; if it is black in the mask, widen YT_H_MIN/MAX or lower YT_S_MIN. Lighting that is dim or tinted shifts yellow towards orange or green.
The marker jumps to something elseAnother yellow-ish thing is bigger than your object (clothes, wall, skin). Remove it from view, or raise YT_S_MIN / narrow the hue band. The largest blob always wins.
The marker sits on the stick, not the ballThe stick is yellow too. Use a stick of another colour or wrap it in tape.
The line breaks into piecesThe object keeps dropping out of the mask (glare on a shiny surface, motion blur). Lower YT_V_MIN or widen the hue band; brighter, even light helps most.
"Could not open camera 0"Another program (or a demo that did not exit) is holding the webcam. Close it, or pick another camera with --camera 1. On macOS allow camera access for your terminal.
uv pip install fails with "Unknown compiler(s)"You created the venv with the native ARM64 Python. Recreate it with the x86_64 Python as shown in Quick start.
The picture looks flippedThat is the default selfie view. Set YT_MIRROR=0 for the raw orientation.

Output data

Each frame produces a plain dictionary (Pipeline.process(frame)). It is JSON-safe and uses 0-1 coordinates, so it can be sent to a web frontend unchanged. Nothing serves it over the network yet.

{
  "active": true,             // false during the OFF phase
  "secondsLeft": 3.2,         // until the next switch
  "mirrored": true,           // x already flipped to match a selfie view
  "object": {                 // null when nothing is detected (always null while OFF)
    "x": 0.71, "y": 0.43,     // centre, 0-1 from the top-left of the (mirrored) view
    "radius": 0.06            // fraction of frame width
  },
  "trace": [                  // list of line segments; empty right after an OFF switch
    [[0.20, 0.61], [0.23, 0.58], ...],
    [[0.71, 0.43]]
  ]
}

PathRole

tests/test_tracker.py17 tests on synthetic frames with a fake clock.

The tests draw a yellow ball on a stick (plus skin-, blue- and orange-coloured decoys) and drive the clock by hand. They check, among other things, that the path follows the object, that it is erased on every OFF switch over several cycles, that the detector is not run while OFF, and that a lost object breaks the line. They have not been run against many real lighting conditions, so expect to tune the hue band for your camera.
